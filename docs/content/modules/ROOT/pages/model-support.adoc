= Model Support And Qualification

Models separates three different claims:

[arabic]
. *Format support* means the parser and kernels understand the required
artifact metadata and tensor encodings.
. *Integration-tested* means CI downloads a pinned artifact, verifies
its checksum, and runs parsing, tokenization, forward-pass, and
generation tests.
. *Qualified* means an exact artifact also clears a named workload's
correctness and latency gates on a recorded runtime and host.

A model family name alone is not a production qualification.

Generators are graded on how well they answer. For embedders we test that
Models produces the same vectors as llama.cpp, since retrieval quality is a
published property of the weights. See
xref:embeddings.adoc#equivalence-gating[Equivalence Gating].

== Supported Runtime Surface

The GGUF runtime recognizes the `bert`, `llama`, `qwen2`, `qwen3`, `qwen35`,
and `gemma4` metadata prefixes. The `bert` path is a dedicated bidirectional
encoder with learned-bias LayerNorm, GELU feed-forward layers, WordPiece
tokenization, and model-declared mean or CLS pooling. Qwen3.5 support is
currently limited to dense, text-only
GGUF checkpoints; its MoE, vision, and MTP paths are not supported. The
Hugging Face path supports strict Qwen 2/Qwen2.5 BF16, Meta MobileMoE QAT
INT4, and GPT-OSS MXFP4 Safetensors bundles with either one weight file or an
indexed shard set. MobileMoE executes its official 60-expert top-4 graph and
chat template in Java. By default it prepares the mapped checkpoint's projection
weights as row-major Q8 for Vector API execution; set
`-Dmodels.mobilemoe.runtimeLayout=packed-int4` to trade latency for a smaller
runtime footprint. GPT-OSS
implements the official Harmony prompt and tool-call protocol, but its current
serial prompt prefill does not pass the catalog performance gate. Two
layer-wise prefill candidates preserved the independent oracle result but were
31% and 42% slower than the controlled serial baseline, so neither is shipped;
the next performance gate targets the measured MXFP4 expert hot loop. The CACT path
supports the released Needle 2 architecture and mixed CQ2/CQ4
artifact layout. `ChatTemplate.NEEDLE2` implements its official raw-schema
prompt protocol, including optional system facts and array-wrapped parallel
tool calls.

Projection kernels support:

* F32
* BF16
* MXFP4
* CQ2 and CQ4
* Q4_0
* Q5_0
* Q8_0
* Q4_K
* Q5_K
* Q6_K

Embedding rows additionally support F16. The tokenizer layer supports BERT
WordPiece, T5/SentencePiece unigram, GPT-2-style byte-level BPE, and Llama
SentencePiece metadata, including Unicode, byte fallback, BOS/EOS controls,
and modern and legacy linear RoPE scaling.

Other architectures, multimodal inputs, remaining quantization formats,
and arbitrary chat templates are not implied by this list.

== Qualified Safetensors Bundle

Qwen2.5 0.5B Instruct BF16 is the first qualified Safetensors bundle. Models
maps its pinned Hugging Face files directly and reaches the `USABLE` tier on
the controlled EPYC host: 1,692.0 ms p95 TTFT, 14.51 tokens/second median
decode, and 3,629.7 ms p95 end-to-end latency. All 27 grounded answers are
correct; 15 retain model text, nine use validated extractive fallback, and
three correctly abstain. A pinned Transformers 4.46.3 run over the same bytes,
host, prompts, and greedy controls supplies the reference comparator. See the
{url-models-github}/tree/main/benchmark-results/certified-20260825/rag/qwen2.5-0.5b-instruct-bf16[retained reports^].

Meta MobileMoE-S QAT INT4 G32 is the first qualified mixture-of-experts
Safetensors bundle. Its complete graph, tokenizer, prompt template, KV state,
and kernels remain in process and pure Java. On the controlled eight-vCPU EPYC
host it reaches `PRODUCTION_READY`: 27/27 correct requests, 958.0 ms p95 TTFT,
21.83 tokens/second median decode, and 2,315.6 ms p95 end-to-end latency. The
official PyTorch full-logit oracle and batched-versus-sequential KV test retain
their original numerical floors. See the
{url-models-github}/tree/main/benchmark-results/certified-20260902/rag/mobilemoe-s-qat-int4-g32[retained reports^].

== Newly Qualified Qwen Artifacts

Qwen3.5 0.8B Q4_K_M now clears the unchanged `USABLE` gate after the Java
Vector API convolution/gate work and the narrowly scoped Gated DeltaNet FFM
kernel. Across 27 measured requests it answers every grounded case correctly,
reaches 1,413.0 ms p95 TTFT, 80.61 tokens/second median decode, and 1,648.6 ms
p95 end-to-end latency. Its decode throughput is 128.5% of Ollama and its p95
end-to-end latency is 1.34x Ollama on the same 16-core EPYC host.

Qwen2.5 3B Instruct Q4_K_M also clears the `USABLE` gate: 1,085.4 ms p95 TTFT,
29.45 tokens/second median decode, and 2,046.7 ms p95 end-to-end latency. Its
decode throughput is 87.8% of Ollama and its p95 end-to-end latency is 1.35x
Ollama. All 27 grounded answers are correct and 24 retain model-written text.

Qwen3.5 4B Q4_K_M remains integration-tested rather than production-qualified.
Pinned llama.cpp references verify its first token and grouped Gated DeltaNet
value-head mapping. See the
{url-models-github}/tree/main/benchmark-results/freetoken-compatibility-20260829[retained compatibility and optimization audit^].

== Supported But Not RAG-Qualified

H2O Danube3 500M Q4_K_M remains integration-tested, but its corrected
structured-prompt run retains model output for only 3 of 27 requests. That
11.1% rate fails the 33.3% contribution floor, so it is excluded from the
qualified identities above. See the
{url-models-github}/tree/main/benchmark-results/certified-20260825/rag/h2o-danube3-500m-q4_k_m[superseding evidence^].

The DeepSeek-Coder fixture exercises mixed
Q4_K/Q5_0/Q8_0/Q6_K tensors and legacy linear RoPE

metadata, and Llama-style byte BPE. Qwen2.5-Math exercises Q6_K

Pinned greedy-token references compare selected GGUF fixtures with a recorded
llama.cpp revision. The MiniLM fixture pins WordPiece token IDs and runs the
standard eight-probe gate against normalized llama.cpp embeddings from the
identical artifact; its measured minimum cosine is 0.99924 against the 0.999
floor. The Granite fixture pins multilingual T5/SentencePiece unigram tokens
and reaches 0.999746 minimum cosine against normalized llama.cpp embeddings
from the checksum-pinned artifact. Safetensors fixtures use pinned Hugging Face Transformers
token/logit and same-host RAG references. Needle 2 uses the checksum-pinned
official CACT artifact and engine behavior; CI also generates and parses the
reference weather tool call through the public template API. GPT-OSS uses pinned
Transformers logits and greedy-generation oracles plus a real Spring AI tool loop. These
are test oracles and benchmark comparators, not runtime dependencies. The list includes
compatibility fixtures as well as qualified catalog artifacts; consult the production
ledger before treating a fixture as deployable.

== Backend Qualification

Backend choice is attached to an exact runtime profile. A model may
qualify with pure Java on one JDK and host and use a native kernel on
another. The ModelJars profile adapter supplies recommendations only
when the model SHA and complete selector match.

Most qualified GGUF artifacts use the Models Rust/FFM backend to stay near
local-runtime latency. Qwen3 0.6B Q4_0, Qwen2.5 0.5B BF16, and MobileMoE-S QAT
INT4 G32 have qualified pure-Java paths. Newer JDKs are re-evaluated so
profiles can move back to pure Java when they clear the same gate.

== Catalog Metadata

{url-modeljars}[ModelJars.org^] supplies versioned marker artifacts
and catalog metadata such as:

* upstream model and revision
* license
* architecture and parameter count
* quantization and file size
* SHA-256
* capabilities, domains, and tags
* estimated memory requirements
* supported backends
* measured runtime recommendations
* qualification report links

Models consumes this through a registry-neutral backend configuration.
The catalog can evolve independently without hardcoding every model in
the runtime or website.
