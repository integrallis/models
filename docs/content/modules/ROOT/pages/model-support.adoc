= Model Support And Qualification

Models separates three different claims:

[arabic]
. *Format support* means the parser and kernels understand the required
GGUF metadata and tensor encodings.
. *Integration-tested* means CI downloads a pinned artifact, verifies
its checksum, and runs parsing, tokenization, forward-pass, and
generation tests.
. *Qualified* means an exact artifact also clears a named workload's
correctness and latency gates on a recorded runtime and host.

A model family name alone is not a production qualification.

== Supported Runtime Surface

The decoder currently recognizes `llama`, `qwen2`, `qwen3`, and `gemma4` GGUF
metadata prefixes.

Projection kernels support:

* F32
* Q4_0
* Q5_0
* Q8_0
* Q4_K
* Q5_K
* Q6_K

Embedding rows additionally support F16. The tokenizer layer supports
GPT-2-style byte-level BPE and Llama SentencePiece metadata, including
Unicode, byte fallback, BOS/EOS controls, and modern and legacy linear
RoPE scaling.

Other architectures, multimodal inputs, remaining quantization formats,
and arbitrary chat templates are not implied by this list.

== Integration-Tested But Not Qualified

Gemma 4 26B-A4B Instruct Q4_K_M is supported by the Java transformer and
Models Rust/FFM projection backend. The exact 16,796,015,136-byte artifact
passed pinned-artifact installation, deterministic generation, direct runtime,
LangChain4j, Spring AI, and guarded-RAG checks. All 27 qualification requests
were correct, including all 21 retained model answers.

The same run is classified `OFFLINE`: p95 TTFT was 3,793.7 ms, above the
2,000 ms usable ceiling. It is therefore integration-tested but intentionally
excluded from the qualified identities above. The
{url-models-github}/blob/main/GEMMA4_QUALIFICATION.md[transfer and qualification
analysis^] and
{url-models-github}/tree/main/benchmark-results/certified-20260802/rag/gemma4-26b-a4b-q4_k_m[retained reports^]
record the result without promoting a failed latency profile.

== Strict Integration Fixtures

The default and dedicated integration suites include:

* Qwen3 0.6B Q4_0, 1.7B Q8_0, and 8B Q4_K_M
* Qwen2.5-Coder 0.5B and 1.5B in Q4_0 and Q8_0, plus 3B Q4_0
and 7B Q4_0
* SmolLM2 360M Q8_0 and SmolLM3 3B Q4_K_M
* TinyLlama 1.1B Chat Q4_0
* DeepSeek-Coder 1.3B and 6.7B Q4_K_M
* MiniCPM5 1B Q4_K_M
* Qwen2.5-Math 1.5B Q4_K_M
* DeepSeek-R1-Distill-Qwen 7B Q4_K_M
* SQLCoder-7B-2 Q5_K_M
* Gemma 4 26B-A4B Instruct Q4_K_M

The DeepSeek-Coder fixture exercises mixed
Q4_K/Q5_0/Q8_0/Q6_K tensors and legacy linear RoPE
scaling. MiniCPM5 exercises explicit Q/K/V head widths, 131K context
metadata, and Llama-style byte BPE. Qwen2.5-Math exercises Q6_K
token embeddings.

Pinned greedy-token references compare selected fixtures with a recorded
llama.cpp revision. llama.cpp is a test oracle and benchmark comparator,
not a runtime dependency.

== Backend Qualification

Backend choice is attached to an exact runtime profile. A model may
qualify with pure Java on one JDK and host and use a native kernel on
another. The ModelJars profile adapter supplies recommendations only
when the model SHA and complete selector match.

Most qualified artifacts use the Models Rust/FFM backend to stay near
local-runtime latency. Qwen3 0.6B Q4_0 has a qualified pure-Java
path. Newer JDKs are re-evaluated so profiles can move back to pure Java
when they clear the same gate.

== Catalog Metadata

{url-modeljars}[ModelJars.org^] supplies versioned marker artifacts
and catalog metadata such as:

* upstream model and revision
* license
* architecture and parameter count
* quantization and file size
* SHA-256
* capabilities, domains, and tags
* estimated memory requirements
* supported backends
* measured runtime recommendations
* qualification report links

Models consumes this through a registry-neutral backend configuration.
The catalog can evolve independently without hardcoding every model in
the runtime or website.
