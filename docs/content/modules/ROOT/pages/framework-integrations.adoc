= Framework Integrations

All framework adapters delegate to the same Models backend contracts.
They do not proxy a local HTTP server or choose a separate inference
implementation. Backend diagnostics remain available so applications can
inspect the selected plan.

Compatibility CI exercises Spring AI 1.1.4, 1.1.8, and 2.0.0 and
LangChain4j 1.0.0, 1.13.1, and 1.17.2. The common Spring AI floor for
the Models and Vectors starters is 1.1.4.

== Plain Java

Add ModelJars and the marker for the selected qualified artifact:

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("org.modeljars:modeljars:{modeljars-version}")
    implementation(
        "org.modeljars.huggingface:" +
            "ggml-org.qwen3-0.6b-gguf.q4_0:" +
            "3.0.0-q4_0.1"
    )
}
----

`ModelJars.open` returns the high-level contract shared by the framework
adapters:

[source,java]
----
import static org.modeljars.catalog.Qwen3_0_6b_Q4_0.MODEL;

import com.integrallis.models.api.SamplingOptions;
import com.integrallis.models.api.TextGenerationModel;
import com.integrallis.models.runtime.chat.ChatMessage;
import com.integrallis.models.runtime.chat.ChatTemplate;
import java.util.List;
import org.modeljars.ModelJars;

var options = SamplingOptions.builder()
    .temperature(0.0f)
    .maxTokens(64)
    .build();

try (TextGenerationModel model = ModelJars.open(MODEL)) {
    var prompt = ChatTemplate.CHATML_NO_THINK.render(
        List.of(ChatMessage.user("Summarize the retrieved context.")));
    String answer = model.generate(prompt, options);

    System.out.println(answer);
    System.out.println(model.diagnostics().optimizations());
}
----

The segmented prompt keeps chat-template controls distinct from message text,
so control-token text inside retrieved or user-provided content cannot create a
new chat turn. The LangChain4j and Spring AI adapters apply the same segmented
rendering automatically.

== LangChain4j

`models-langchain4j` provides `ModelsChatModel`. It adapts LangChain4j
chat requests to a Models backend and exposes the backend diagnostics
used for the request. `ModelsStreamingChatModel` implements the matching
streaming contract. The application selects the LangChain4j version;
the Models adapter does not add one transitively.

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("dev.langchain4j:langchain4j:1.17.2")
    implementation("org.modeljars:modeljars:{modeljars-version}")
    implementation(
        "org.modeljars.huggingface:" +
            "ggml-org.qwen3-0.6b-gguf.q4_0:" +
            "3.0.0-q4_0.1"
    )
    implementation("com.integrallis:models-langchain4j:{models-version}")
}
----

[source,java]
----
import static org.modeljars.catalog.Qwen3_0_6b_Q4_0.MODEL;

import com.integrallis.models.api.SamplingOptions;
import com.integrallis.models.langchain4j.ModelsChatModel;
import com.integrallis.models.runtime.chat.ChatTemplate;
import org.modeljars.ModelJars;

var options = SamplingOptions.builder()
    .temperature(0.0f)
    .maxTokens(128)
    .build();

try (var runtime = ModelJars.open(MODEL)) {
    var model = new ModelsChatModel(
        runtime,
        ChatTemplate.CHATML_NO_THINK,
        options);
    String answer = model.chat("Answer using only the supplied context.");

    System.out.println(answer);
    System.out.println(model.diagnostics().backend());
}
----

=== RAG with Vectors

`vectors-langchain4j` implements LangChain4j's standard
`EmbeddingStore<TextSegment>`. It composes directly with the Models chat
adapter in `AiServices`; no Models-to-Vectors bridge or HTTP process is
required.

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("com.integrallis:vectors-langchain4j:{vectors-version}")
}
----

[source,java]
----
import static org.modeljars.catalog.Qwen3_0_6b_Q4_0.MODEL;

import com.integrallis.models.api.SamplingOptions;
import com.integrallis.models.langchain4j.ModelsChatModel;
import com.integrallis.models.runtime.chat.ChatTemplate;
import com.integrallis.vectors.core.SimilarityFunction;
import com.integrallis.vectors.db.IndexType;
import com.integrallis.vectors.db.VectorCollection;
import com.integrallis.vectors.langchain4j.JavaVectorsEmbeddingStore;
import dev.langchain4j.rag.content.retriever.EmbeddingStoreContentRetriever;
import dev.langchain4j.service.AiServices;
import org.modeljars.ModelJars;

interface Assistant {
    String answer(String question);
}

var options = SamplingOptions.builder()
    .temperature(0.0f)
    .maxTokens(128)
    .build();
var collection = VectorCollection.builder()
    .dimension(embeddingModel.dimension())
    .metric(SimilarityFunction.COSINE)
    .indexType(IndexType.HNSW)
    .build();

try (var runtime = ModelJars.open(MODEL);
     var store = JavaVectorsEmbeddingStore.builder(collection)
         .commitAfterAdd(true)
         .build()) {
    var retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingModel(embeddingModel)
        .embeddingStore(store)
        .maxResults(4)
        .build();

    var assistant = AiServices.builder(Assistant.class)
        .chatModel(new ModelsChatModel(
            runtime,
            ChatTemplate.CHATML_NO_THINK,
            options))
        .contentRetriever(retriever)
        .build();

    String answer = assistant.answer("What does the retrieved policy allow?");
}
----

== Spring AI

`models-spring-ai` provides blocking and streaming chat model adapters.
Both paths use the same tokenizer, generation loop, sampler, and
selected backend as plain Java. The application selects the Spring AI
version, normally through its Spring AI BOM.

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("org.springframework.ai:spring-ai-model:2.0.0")
    implementation("org.modeljars:modeljars:{modeljars-version}")
    implementation(
        "org.modeljars.huggingface:" +
            "ggml-org.qwen3-0.6b-gguf.q4_0:" +
            "3.0.0-q4_0.1"
    )
    implementation("com.integrallis:models-spring-ai:{models-version}")
}
----

[source,java]
----
import static org.modeljars.catalog.Qwen3_0_6b_Q4_0.MODEL;

import com.integrallis.models.api.SamplingOptions;
import com.integrallis.models.runtime.chat.ChatTemplate;
import com.integrallis.models.spring.ai.ModelsSpringAiChatModel;
import org.springframework.ai.chat.prompt.Prompt;
import org.modeljars.ModelJars;

var options = SamplingOptions.builder()
    .temperature(0.0f)
    .maxTokens(128)
    .build();

try (var runtime = ModelJars.open(MODEL)) {
    var model = new ModelsSpringAiChatModel(
        runtime,
        ChatTemplate.CHATML_NO_THINK,
        options);

    String answer = model.call("Answer using only the supplied context.");
    System.out.println(answer);

    model.stream(new Prompt("List the cited facts."))
        .map(response -> response.getResult().getOutput().getText())
        .doOnNext(System.out::print)
        .blockLast();
}
----

== Spring Boot

`models-spring-boot-starter` creates the local
`ModelsSpringAiChatModel` from an application-provided
`TextGenerationModel` or `InferenceBackend`. The Vectors starter
independently creates the Spring AI `VectorStore` from the application's
`EmbeddingModel`; both starters can run in the same application context.
An application that already uses a Spring AI model-provider starter does
not need the explicit `spring-ai-model` dependency shown below.

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("org.springframework.ai:spring-ai-model:2.0.0")
    implementation("org.modeljars:modeljars:{modeljars-version}")
    implementation(
        "org.modeljars.huggingface:" +
            "ggml-org.qwen3-0.6b-gguf.q4_0:" +
            "3.0.0-q4_0.1"
    )
    implementation("com.integrallis:models-spring-boot-starter:{models-version}")
    implementation("com.integrallis:vectors-spring-boot-starter:{vectors-version}")
}
----

Open the selected marker as a Models runtime bean. The starter exposes it
as the Spring AI bean named `modelsChatModel`:

[source,java]
----
import static org.modeljars.catalog.Qwen3_0_6b_Q4_0.MODEL;

import com.integrallis.models.api.TextGenerationModel;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.modeljars.ModelJars;

@Configuration
class LocalModelConfiguration {
    @Bean(destroyMethod = "close")
    TextGenerationModel localModel() {
        return ModelJars.open(MODEL);
    }
}
----

Configure the model-facing chat envelope and sampling defaults separately
from the Vectors index:

[source,yaml]
----
integrallis:
  models:
    chat-template: chatml-no-think
    sampling:
      temperature: 0.0
      max-tokens: 128

java-vectors:
  index-type: HNSW
  quantizer: SQ8
----

When a Spring AI `EmbeddingModel` bean is available,
`vectors-spring-boot-starter` infers its dimension and contributes
`JavaVectorsVectorStore`. Spring AI's `ChatClient` and RAG advisors can
therefore inject the named local chat model and the standard
`VectorStore` without adapter-specific glue.

== Guarded RAG

`models-rag` is a framework-neutral grounding policy for small local
models. Apply it to text returned by plain Java, LangChain4j, or Spring
AI:

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("com.integrallis:models-rag:{models-version}")
}
----

[source,java]
----
import com.integrallis.models.rag.GroundedAnswer;
import com.integrallis.models.rag.GroundedAnswerPolicy;
import com.integrallis.models.rag.GroundingDocument;
import java.util.List;

var evidence = List.of(
    new GroundingDocument(
        "policy-17",
        "Cancellation policy",
        "Orders can be cancelled without charge before shipment.",
        4.2f,
        1));
String generatedText =
    "Orders can be cancelled without charge before shipment. [policy-17]";

GroundedAnswer answer = GroundedAnswerPolicy.productionDefault().apply(
    "When can an order be cancelled?",
    evidence,
    generatedText);

System.out.println(answer.decision());
System.out.println(answer.text());
----

The result records the chosen outcome and retains raw generated text for
audit. See xref:rag.adoc[Guarded RAG] for retrieval gates, citation
validation, and extractive fallback.

`models-rag-bench` exercises the policy through:

* plain Java
* LangChain4j
* Spring AI
* revision-matched Ollama
* revision-matched llama.cpp
* configured hosted APIs

Every client receives the same corpus, retrieval result, prompt hash,
sampling controls, and deterministic correctness checks. See the
{url-models-github}/blob/main/models-rag-bench/README.md[benchmark
application^] and {url-models-github}/blob/main/RAG_BENCHMARKS.md[production
RAG results^].

== Embedding Storage

`models-embedding` is the optional bridge to Vectors. It uses released
`vectors-db` and `vectors-cache-semantic-db` modules for storage,
search, and semantic caching without adding those dependencies to the
core generation API.

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("com.integrallis:models-embedding:{models-version}")
}
----

An `EmbeddingBackend` and `VectorCollection` must use the same vector
dimension. `VectorCollectionEmbeddingSink` owns and closes the embedding
backend; the application retains ownership of the collection. Batch documents,
commit once, and embed the query with the same backend:

[source,java]
----
import com.integrallis.models.embedding.EmbeddingBackend;
import com.integrallis.models.embedding.VectorCollectionEmbeddingSink;
import com.integrallis.vectors.db.SearchRequest;
import com.integrallis.vectors.db.VectorCollection;
import java.util.List;

static void indexAndSearch(
        EmbeddingBackend embeddings,
        VectorCollection documents) {
    try (var sink = new VectorCollectionEmbeddingSink(embeddings, documents)) {
        sink.putAll(
            List.of("policy-17", "shipping-4"),
            List.of(
                "Orders can be cancelled before shipment.",
                "Standard shipping takes three business days."));
        documents.commit();

        float[] query = sink.backend().embed("When can I cancel an order?");
        var results = documents.search(
            SearchRequest.builder(query, 5).build());
        results.hits().forEach(hit -> System.out.println(hit.id()));
    }
}
----

The sink validates every vector returned by the backend before mutating the
collection. A wrong batch size, null row, or mismatched dimension is reported as
an embedding-backend contract violation rather than a later index error.
