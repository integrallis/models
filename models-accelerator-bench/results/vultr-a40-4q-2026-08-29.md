# Java GPU full-model result: Vultr NVIDIA A40-4Q

Date: 2026-08-29

The second NVIDIA gate used a Vultr `vcg-a40-2c-10g-4vram` instance: an NVIDIA A40-4Q with
4,096 MiB advertised VRAM, 2 vCPUs, and driver 550.90.07. The runtime reported 3,917.7 MiB global
memory and a 3,271.7 MiB maximum allocation. The tested artifact was the same checksum-pinned
Qwen3 0.6B Q4_0 GGUF used by the A16 gate.

The capacity selector estimated 1,074.2 MiB for retained 32-token prefill and single-token decode
plans and selected the PTX GPU. The 250-token prompt and exact eight-token greedy decode probe both
preserved CPU/GPU output parity:

| Path | Warm prefill | Decode p50 | Eight-token decode |
|---|---:|---:|---:|
| Vector API | 9.453 s | 87.056 ms | 704.378 ms |
| Java/Tornado PTX | 2.150 s | 65.767 ms | 583.864 ms |

Warm prefill improved `4.40x`; median decode latency improved `1.32x`. Eager readiness compiled the
223 retained plans in 13.554 seconds. This validates capacity selection and exact output parity on a
second NVIDIA architecture and a larger allocation. It does not qualify OpenCL or SPIR-V devices.

The final public-API gate loaded the same artifact through
`TornadoBackend.open(..., requireAccelerator=true)`. It selected `cuda-0`, retained 223 plans,
completed readiness in 13.124 seconds, and generated the exact Vector API control text `JAVA`.
