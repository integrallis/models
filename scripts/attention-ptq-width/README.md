# Reachable fixed-width component diagnosis

This harness measures existing grouped attention scores/softmax and Java PTQ1_0×Q8_0 row products. It does not change production arithmetic or claim whole-model qualification. Grouped attention is the Granite/default-fallback or explicit-plan path; PTQ is the Java/unsupported-native route, not the normal native PTQ projection.

Four fresh-JVM same-host process pairs per component compare the frozen production class with an independent primitive reference. The control keeps eight logical score/sum lanes, the exact fold, true FMA, integer PTQ grouping and scale-FMA order. Thirty-one changing-input output signatures and cold/hot signatures must match exactly. Warmup is fixed at 2,000 calls; five measured blocks each run at least 250 ms, checking time only after a 992-call score/softmax batch or 1020-call PTQ batch. Each batch contains full 31-input or 255-input mutation cycles. Actual call counts/durations are retained, and no block is discarded. All inputs/output buffers are retained. Softmax resets its input using the same arraycopy in both arms. Cold allocation includes each arm's own first-use initialization; warmed allocation and latency are recorded separately. These synthetic shapes are diagnosis, not model performance claims.

JDK 25.0.3, actual CPU/VM flags, frozen source/classes and downloaded dependency hashes are retained. Each pair uploads before the next pair. Separate JFR processes attribute allocations; their latency is never pooled with uninstrumented measurements. No failed process or partial run becomes a passing result.
